# TrackHer Issues — August 2, 2026

Bugs and UX issues identified from TestFlight screenshots.

---

## 1. Quick Log: single symptom selection only

**Severity:** Medium (UX friction)
**Screenshot:** Image 1 — Carpal Tunnel Symptoms quick log sheet

The quick log sheet only allows selecting one symptom at a time. Users must log, close, reopen, and select the next symptom to record multiple symptoms in a single session.

**Root cause:** `quickLogStore.ts` stores `selectedSymptomId: string | null` — a single value, not an array. The entire `QuickLogSheet.tsx` flow (severity slider, trigger tags, duration) is built around one symptom per submission.

**Files:**
- `src/stores/quickLogStore.ts` — single `selectedSymptomId` state
- `src/components/dashboard/QuickLogSheet.tsx` — sheet UI, lines 78–80 consume the single ID

**Suggested fix:** Either allow multi-select with a shared severity (batch log), or add a "Log another" flow that loops back to symptom selection after each submission without closing the sheet.

## 2. Dashboard charts unreadable with long-term data

**Severity:** Medium (UX degradation over time)
**Screenshot:** Image 2 — Energy/Mood/Sleep bar charts are dense and noisy with ~1 year of data

The Energy, Mood, and Sleep pulse charts render every daily data point as a bar. With months/years of data, bars compress to 1–2px wide, creating a solid unreadable mass.

**Files:**
- `src/components/dashboard/StoryChartsBody.tsx` — renders pulse channels as `<Bar>` elements in Recharts, no aggregation
- `src/components/dashboard/StoryColumn.tsx` — parent; passes `chartData` which is daily-granularity

**Suggested fixes:**
- Aggregate to weekly averages when data exceeds ~90 days
- Switch from bar chart to area/line chart for long ranges
- Add date range zoom or a window selector (the `DateRangeSelector` component exists but may not be wired to these charts)
- Consider a rolling-average overlay to show trend

## 3. Welcome message placement

**Severity:** Low–Medium (onboarding UX)
**Screenshot:** Image 3 — "Welcome to TrackHer" card appears mid-dashboard

The welcome card renders between `UnlockProgress` and `ScoreSummaryCards` in `DashboardLayout.tsx` (line 160). For a user with populated data, it looks misplaced buried in the middle of the dashboard.

**Files:**
- `src/components/dashboard/WelcomeMessage.tsx` — the card itself; checks `welcome_dismissed` UI flag
- `src/components/dashboard/DashboardLayout.tsx` — line 160 renders `<WelcomeMessage />` after `<UnlockProgress />`

**Suggested fixes:**
- Move it to the very top of the dashboard (before `LunaDashboardCard`) or render it as a full-screen onboarding modal on first launch
- Auto-dismiss if the user already has check-in data (the `welcome_dismissed` flag is currently only set on manual dismiss)

## 4. Luna chat: "Edge Function returned a non-2xx status code"

**Severity:** High (feature broken)
**Screenshots:** Images 3, 4, 10 — error appears in Luna composer area

The Supabase Edge Function `ai-assistant` is returning HTTP errors. The error string comes from Supabase's `functions.invoke()` — specifically `fnError.message` in `useAiAssistant.ts` line 140. The "Edge Function returned a non-2xx status code" message is Supabase's default error text when the function returns a 4xx/5xx.

**Files:**
- `src/hooks/useAiAssistant.ts` — `invokeAiAssistant()` function, lines 134–155
- `src/components/luna/LunaComposer.tsx` — renders `assistantError` in lines 34–38
- Edge Function: `supabase/functions/ai-assistant` (not in this repo tree — server-side)

**Likely causes:**
- OpenAI API key expired/misconfigured in the Edge Function environment
- Edge Function deployment out of date or crashed
- Rate limiting or quota exceeded on the AI provider

**Suggested fix:** Debug the Edge Function logs in the Supabase dashboard. The client-side error handling is correct; this is a server-side issue.

## 5. Luna chat sheet: pull-up reveals content behind

**Severity:** Medium (visual glitch, feels broken on iOS)
**Screenshots:** Images 4, 5 — pulling up on the composer bar reveals the page content underneath

The Luna panel is a portal (`createPortal` to `document.body`) with `position: fixed` and a backdrop. On mobile, the panel is `h-full w-full` but the underlying page content can show through when the user drags the composer area upward, because there's no gesture dismiss guard and the fixed positioning doesn't prevent rubber-banding of the panel itself within the WebView.

**Files:**
- `src/components/luna/LunaProvider.tsx` — lines 616–763, the panel portal
- `src/components/luna/LunaComposer.tsx` — the bottom composer div
- `src/components/luna/LunaTranscript.tsx` — has `overscroll-contain` on the scroll container (line 110), but the outer panel wrapper does not

**Suggested fix:** Add `overscroll-behavior: contain` and `touch-action: none` to the outer Luna panel container (the `div` at line 620) so that touch events don't propagate through to the underlying page. Alternatively, implement a proper iOS-style sheet dismiss gesture handler similar to `QuickLogSheet.tsx`'s drag-to-dismiss.

## 6. Lab detail modal: X button / title collide with iOS status bar

**Severity:** High (broken layout, usability)
**Screenshots:** Images 6, 7 — date title and X button overlap the iOS status bar and notch area

The Lab detail modal uses `size="lg"` which gives it `max-h-[85dvh]`. On mobile, the modal anchors to the bottom (`items-end`). When the content is tall enough, the modal reaches the top of the viewport and the header (`px-4 pt-4`) has no safe area inset — unlike `size="full"` which gets `safe-area-modal-header`.

**Files:**
- `src/components/labs/LabDetailModal.tsx` — line 66: `size="lg"`
- `src/components/ui/Modal.tsx` — lines 109–112: safe area class only applied when `isFullScreen`
- `src/index.css` — lines 307–311: `.safe-area-modal-header` definition

**Suggested fixes:**
- Option A: Change the lab detail modal to `size="full"` on mobile so it gets proper safe area handling
- Option B: Apply safe area top padding to ALL modal sizes when the modal's computed height would reach the status bar (use `max()` with `env(safe-area-inset-top)` in the non-full header too)
- Option C: Cap the non-full modal's top edge so it never enters the safe area zone (e.g., `top: env(safe-area-inset-top)` on the container)

## 8. Luna chat: keyboard glitch

**Severity:** Medium (UX)
**Screenshot:** Image 8 — keyboard appears over the Luna chat panel in a broken layout

The Capacitor config uses `resize: 'none'` for the keyboard plugin (`capacitor.config.ts` line 17), relying on `useVisualViewportBounds` to reposition content. The Luna panel sets its container height via `style={{ top: offsetTop, height: viewportHeight }}` (LunaProvider.tsx line 621), but the composer may not be adjusting correctly when the keyboard appears, causing the input to be hidden behind or overlap with the keyboard.

**Files:**
- `capacitor.config.ts` — `resize: 'none'` Keyboard config
- `src/hooks/useKeyboardBottomInset.ts` — visual viewport tracking hook
- `src/components/luna/LunaProvider.tsx` — lines 620–621: viewport-based positioning
- `src/components/luna/LunaComposer.tsx` — composer with `pb-[max(0.75rem,env(safe-area-inset-bottom))]`

**Suggested fix:** Verify `useVisualViewportBounds` correctly accounts for keyboard height on iOS Capacitor. The composer's bottom padding uses `env(safe-area-inset-bottom)` but should also account for keyboard inset. Test with the Capacitor Keyboard plugin's `keyboardWillShow`/`keyboardDidShow` events.

## 9. Check-In: no way to delete tracked symptoms

**Severity:** Medium (data management)
**Screenshot:** Image 9 — long list of tracked symptoms with no delete option

The `SymptomManageModal` allows toggling symptoms on/off (tracked vs. untracked), and the description says "Removing a symptom stops future prompts without deleting its history." However, there's no UI to bulk-remove symptoms or to indicate which ones are active vs. inactive in the Check-In symptom grid.

The Check-In page's symptom grid (Image 9) shows every symptom the user has ever tracked, with no way to hide or remove them from the display.

**Files:**
- `src/components/checkin/SymptomManageModal.tsx` — toggle tracked on/off, but no "remove from list entirely" action
- `src/pages/CheckinPage.tsx` — line 370: renders `SymptomManageModal`
- `src/components/dashboard/QuickLogWidget.tsx` — line 138: also renders `SymptomManageModal`

**Suggested fix:** Add a visible "remove" action (swipe-to-delete or explicit remove button) in the symptom manage modal, and/or filter the Check-In grid to only show currently-tracked symptoms with an option to show archived ones.
