## Dark mode — what to know before touching it again

`--color-sand-50` is duplicated in **five** places and they must move together or the native
window seams during rubber-band overscroll: `src/index.css`, the dark `theme-color` meta in
`index.html`, `appBackground` in `AppDelegate.swift` and `BridgeViewController.swift`, and
`--iconBackgroundColorDark` in `package.json`. Current value `#242124`.

Surface stops interleave across two ramps and the luminance order is load-bearing —
`sand-50 < sand-100 < sage-50 < sand-200 < sage-100 < sage-200 < sand-300 < sage-300 <
sand-400 < sage-400`. `sage-50` is the header hover background; drop it below `sand-100`
and hovers darken instead of lifting.

All rose accents (sage-500–900, clay, severity, heatmap stops) were deliberately left
untouched so the surface change could be judged alone. If the pinks still read hot on
device, the next lever is chroma on `sage-500`/`600` and the severity ramp — not more lift.
`--color-chart-band-conventional` is still `#8a6478`, the old plum sage-400, and is now the
only plum-tinted token in dark mode.

  (`vitest run src/lib src/utils/__tests__`) or let CI do it. `tsc --noEmit` is fast and clean.

  oxlint. A fresh `npm ci` on the Mac will prune the Linux ones and break sandbox test runs
  again; `npm i --no-save @rolldown/binding-linux-arm64-gnu @oxlint/binding-linux-arm64-gnu`
  restores them.
- `npm run build` cannot run in the Linux sandbox — Mac-native binaries. CI is the only
  automated place a real build happens.
